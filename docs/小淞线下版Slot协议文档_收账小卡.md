## 协议概述

GD收账小卡是小淞线下版老虎机使用的通信协议，用于电脑与机台之间的数据交换。

### 主要特性

- ✅ **登入机制**: 必须先登入才能操作上下分
- ✅ **外部码表**: 开分码表和洗分码表记录外部按钮操作金额
- ✅ **4字节BCD**: 每字节十六进制值转十进制后代表2位数字
- ✅ **双重校验**: SUM1（ADD累加）+ SUM2（XOR异或）
- ✅ **主动心跳**: 开机时主动发送FAH，错误时发送E1

## 数据格式

### 4字节BCD格式

每个字节的十六进制值转换为十进制后，代表2位数字。

**示例**:
```
十六进制: 05 14 31 0B
转十进制: 5  20  49  11
拼接结果: 05 20 49 11 → 5204911
单位:     分
金额:     52049.11 元
```

**转换公式**:
```
值 = (字节1 × 1000000) + (字节2 × 10000) + (字节3 × 100) + 字节4
```

其中每个字节值为其十六进制值转十进制的结果。

## 校验算法

### SUM1 计算（ADD累加）

对数据部分的每个字节进行累加，取最后2位（& 0xFF）。

**公式**:
```
SUM1 = (Byte1 + Byte2 + ... + ByteN) & 0xFF
```

**示例**:
```
数据: A5 05 C0
计算: (0xA5 + 0x05 + 0xC0) & 0xFF
    = (165 + 5 + 192) & 0xFF
    = 362 & 0xFF
    = 0x6A
结果: 6A
```

### SUM2 计算（XOR异或）

对数据部分的每个字节进行异或，再与SUM1异或，取最后2位。

**公式**:
```
SUM2 = (Byte1 ^ Byte2 ^ ... ^ ByteN ^ SUM1) & 0xFF
```

**示例**:
```
数据: A5 05 C0
SUM1: 6A
计算: (0xA5 ^ 0x05 ^ 0xC0 ^ 0x6A) & 0xFF
    = (165 ^ 5 ^ 192 ^ 106) & 0xFF
    = 0x0A
结果: 0A
```

**功能**: 查询开分状态、洗分状态、转数、状态码

**发送格式**:

```

#### 3. 资金操作指令

##### 3.1 A5 XX C0 - 上分

**功能**: 开分（XX = 开分次数）

**发送格式**:
```
A5 [次数] C0 [SUM1] [SUM2]
```

**参数说明**:
- `A5`: 指令头（固定）
- `XX`: 开分次数（十六进制，如 05 = 5次）
- `C0`: 不洗分标志（固定）
- `SUM1`: ADD校验码
- `SUM2`: XOR校验码

**示例**（开分5次）:
```
发送: A5 05 C0 6A 0A

校验计算:
SUM1 = (0xA5 + 0x05 + 0xC0) & 0xFF = 0x6A
SUM2 = (0xA5 ^ 0x05 ^ 0xC0 ^ 0x6A) & 0xFF = 0x0A
```

**回复**:
```
A5 CA 33  // 成功（CA=成功标志，33=版本号）
A5 C5 33  // 失败（C5=未登入）
```

---

##### 3.2 A5 00 C1 - 下分

**功能**: 洗分

**发送格式**:
```
A5 00 C1 [SUM1] [SUM2]
```

**参数说明**:
- `A5`: 指令头（固定）
- `00`: 不开分（固定）
- `C1`: 洗分标志（固定）
- `SUM1`: ADD校验码
- `SUM2`: XOR校验码

**示例**:
```
发送: A5 00 C1 66 02

校验计算:
SUM1 = (0xA5 + 0x00 + 0xC1) & 0xFF = 0x66
SUM2 = (0xA5 ^ 0x00 ^ 0xC1 ^ 0x66) & 0xFF = 0x02
```

**回复**:
```
A5 CA 33  // 成功
A5 C5 33  // 失败（未登入）
```

---

#### 4. 管理指令

##### 4.1 EA DE - 清除开洗分账+回补数

**功能**: 清除开洗分账和回补次数

**发送格式**:
```
EA DE
```

**说明**: 
- 可多次发送避免漏收
- 无回复

---

##### 4.2 EA E7 - 归0/故障排除

**功能**: 归0并清除故障标记、开分码表、洗分码表

**发送格式**:
```
EA E7
```

**前置条件**:
- 指拨1 = ON 时有效
- 指拨1 = OFF 时无作用

**回复**:
```
EF  // E1错误时：完整归0完成
EE  // 未有E1时：清除账目完成
```

**操作效果**:
- ✅ 清除机台故障标记/故障灯
- ✅ 清除开分码表（外部开分计数器）
- ✅ 清除洗分码表（外部洗分计数器）
- ❌ 不影响服务端数据

### 被动接收回复

#### 1. 主动心跳/事件

##### FAH - 开机信号

**触发时机**: 机版刚开机时主动发送

**格式**:
```
FAH
```

**处理**: 记录开机事件，重新初始化连接状态

---

##### E1 - 记忆体异常

**触发时机**: 
- 显示器显示: E-1（记忆体异常需归0）
- 显示器显示: E-2（收smart卡异常）

**格式**:
```
E1
```

**处理**: 
1. 机台锁定，禁止操作
2. 发送 `EA E7` 归0指令
3. 或使用硬件归0（指拨4切ON）

#### 2. 查询回复

##### A6 - 查询账目回复

**触发指令**: `EA C4`

**回复格式**:
```
A6 [开分标志] [开分码表4字节] [洗分标志] [洗分码表4字节] 
   [卡标志] [开分卡4字节] [机台分数4字节] [SUM1] [SUM2]
```

**完整示例**:
```
A6 C9 05 14 31 0B CA 10 00 63 1E E9 00 04 03 02 00 07 28 00 XX XX
│  │  └─────┬─────┘ │  └─────┬─────┘ │  └─────┬─────┘ └─────┬─────┘ └─┬─┘
│  │   开分码表(4字节) │   洗分码表(4字节) │  开分卡(4字节)   机台分数(4字节) 校验
│  └─ 开分码表标志      └─ 洗分码表标志    └─ 开分卡标志
└─ 回复头
```

**字段详解**:

| 位置 | 字段 | 长度 | 可能值 | 说明 |
|------|------|------|--------|------|
| 0-1 | 回复头 | 1字节 | `A6` | 固定 |
| 2-3 | 开分码表标志 | 1字节 | `C9` | 正常状态 |
|  |  |  | `CB` | 开奖中 |
| 4-11 | 开分码表 | 4字节 | BCD | 外部开分累计金额（分） |
| 12-13 | 洗分码表标志 | 1字节 | `CA` | 固定 |
| 14-21 | 洗分码表 | 4字节 | BCD | 外部洗分累计金额（分） |
| 22-23 | 开分卡标志 | 1字节 | `E9` | 正常 |
|  |  |  | `EE` | 故障（smart卡故障） |
| 24-31 | 开分卡分数 | 4字节 | BCD | 开分卡剩余分数（分） |
| 32-39 | 机台分数 | 4字节 | BCD | 机台当前分数（分） |
| 40-41 | SUM1 | 1字节 | - | ADD校验 |
| 42-43 | SUM2 | 1字节 | - | XOR校验 |

**数据解析示例**:
```
开分码表: 05 14 31 0B
→ 0x05→5, 0x14→20, 0x31→49, 0x0B→11
→ 5204911（分）= 52049.11元

洗分码表: 10 00 63 1E
→ 0x10→16, 0x00→0, 0x63→99, 0x1E→30
→ 16009930（分）= 160099.30元

开分卡分数: 00 04 03 02
→ 0x00→0, 0x04→4, 0x03→3, 0x02→2
→ 40302（分）= 403.02元

机台分数: 00 07 28 00
→ 0x00→0, 0x07→7, 0x28→40, 0x00→0
→ 74000（分）= 740.00元
```

##### A7 D2/D3 - 查询机台情况回复

**触发指令**: `EA D4`

**回复格式**:
```
A7 [开分状态] 00 [回补] [少跳高] [少跳低] [洗分状态] [洗分码表4字节]
   [转数标志] [转数2字节] [连莊] [状态] AC [预留3字节] [SUM1] [SUM2]
```

**完整示例**:
```
A7 D2 00 01 00 00 D6 00 00 00 00 DC 1E 14 00 00 AC xx xx xx XX XX
│  │  │  │  └──┬──┘ │  └─────┬─────┘ │  └──┬──┘ │  │  └──┬──┘ └─┬─┘
│  │  │  │  码表少跳 │   洗分码表(4字节) │  转数值  │  │  预留3字节 校验
│  │  │  └─ 回补次数 │                  │         │  └─ 状态码
│  │  └─ 空置        └─ 洗分状态         │         └─ 累计连莊数
│  └─ 开分状态                           └─ 转数标志
└─ 回复头
```

**字段详解**:

| 位置 | 字段 | 长度 | 可能值 | 说明 |
|------|------|------|--------|------|
| 0-1 | 回复头 | 1字节 | `A7` | 固定 |
| 2-3 | 开分状态 | 1字节 | `D2` | 开分完成 |
|  |  |  | `D3` | 开分中 |
| 4-5 | 空置 | 1字节 | `00` | 固定 |
| 6-7 | 回补次数 | 1字节 | `00`-`FF` | 需回补按钮次数（开分失败次数） |
| 8-9 | 码表少跳高位 | 1字节 | `00` | 开分完成后码表少跳的高位部分 |
| 10-11 | 码表少跳低位 | 1字节 | `00`-`63` | 码表少跳的低位部分（最高63H=99） |
| 12-13 | 洗分状态 | 1字节 | `D6` | 洗分完成 |
|  |  |  | `D7` | 洗分跳表中 |
| 14-21 | 洗分码表 | 4字节 | BCD | 洗分码表金额（分） |
| 22-23 | 转数标志 | 1字节 | `DC` | 固定（Slot专用） |
| 24-25 | 转数高位 | 1字节 | `00`-`FF` | 转数高位（十六进制→十进制） |
| 26-27 | 转数低位 | 1字节 | `00`-`FF` | 转数低位（十六进制→十进制） |
| 28-29 | 累计连莊数 | 1字节 | `00` | 不使用（预留） |
| 30-31 | 状态码 | 1字节 | 见下表 | 机台当前状态 |
| 32-33 | 预留标志 | 1字节 | `AC` | 固定 |
| 34-37 | 预留数据 | 3字节 | - | 预留功能 |
| 38-39 | SUM1 | 1字节 | - | ADD校验 |
| 40-41 | SUM2 | 1字节 | - | XOR校验 |

**状态码说明**:

| 值 | 含义 | 说明 |
|----|------|------|
| `00` | 正常 | 一般状态 |
| `01` | 大当 | 大奖中 |
| `02` | 高确 | 高确率状态 |
| `03` | 大当+高确 | 大奖+高确 |
| `04` | 小当 | 小奖 |
| `1x` | 得分线故障1 | 得分输入信号异常 |
| `2x` | 故障2 | 网络未开分却跳码表 |
| `8x` | 登出状态 | 目前处于登出中 |

**转数计算示例**:
```

→ 0x1E→30, 0x14→20

```

## 使用流程示例

### 示例1：完整操作流程（登入→查询→上分→查询→登出）

```
步骤1：登入
电脑 → 机台: EA C5
机台 → 电脑: A7 C5  (登入成功)

步骤2：查询账目
电脑 → 机台: EA C4
机台 → 电脑: A6 C9 05 14 31 0B CA 10 00 63 1E E9 00 04 03 02 00 07 28 00 XX XX
解析结果:
  - 开分码表: 5204911分 (52049.11元)
  - 洗分码表: 16009930分 (160099.30元)
  - 开分卡: 40302分 (403.02元)
  - 机台分数: 74000分 (740.00元)
  - 状态: C9=正常，E9=开分卡正常

步骤3：上分5次
电脑 → 机台: A5 05 C0 6A 0A
机台 → 电脑: A5 CA 33  (开分成功，版本33H)

步骤4：再次查询账目（验证上分结果）
电脑 → 机台: EA C4
机台 → 电脑: A6 C9 ... (开分码表应该增加)

步骤5：登出
电脑 → 机台: EA C3
机台 → 电脑: A7 C3  (登出成功)
```

### 示例2：故障处理流程

```
步骤1：机台主动报错
机台 → 电脑: E1  (记忆体异常)

步骤2：电脑锁定机台
服务端: 设置 has_lock = 1，禁止所有操作

步骤3：发送归0指令
电脑 → 机台: EA E7
机台 → 电脑: EF  (完整归0完成)

步骤4：解除锁定
服务端: 设置 has_lock = 0
服务端: 清除 external_open_count = 0
服务端: 清除 external_wash_count = 0
服务端: 设置 check_flag (10秒有效)
```

### 示例3：未登入时操作失败

```
步骤1：直接尝试上分（未登入）

机台 → 电脑: A5 C5 33  (操作失败，C5=未登入)

步骤2：先登入
电脑 → 机台: EA C5
机台 → 电脑: A7 C5  (登入成功)

步骤3：再次上分
电脑 → 机台: A5 05 C0 6A 0A
机台 → 电脑: A5 CA 33  (操作成功)
```

---

### 示例4：查询机台情况

```
电脑 → 机台: EA D4
机台 → 电脑: A7 D2 00 01 00 00 D6 10 00 63 1E DC 1E 14 00 00 AC xx xx xx XX XX

解析结果:
  - 开分状态: D2=开分完成
  - 回补次数: 01=需回补1次（1次开分失败）
  - 码表少跳: 00 00=无少跳
  - 洗分状态: D6=洗分完成
  - 洗分码表: 16009930分
  - 转数: 0x1E 0x14 → 30 20 → 3020转
  - 状态码: 00=正常
```

### 示例5：开奖中的状态

```
电脑 → 机台: EA C4
机台 → 电脑: A6 CB ... CA ... E9 ...
                 ↑
                 CB=开奖中（非C9正常状态）

电脑 → 机台: EA D8
机台 → 电脑: A7 D7 ... D9 ...
                 ↑

## 注意事项

### ⚠️ 关键注意事项

1. **登入机制**
   - ✅ 必须先发送 `EA C5` 登入，才能执行上下分操作
   - ❌ 未登入时上下分会收到 `A5 C5 XX` 失败回复
   - 💡 每次连接建立后都需要重新登入

2. **数据格式**
   - ✅ 4字节BCD：每字节hex值转dec代表2位数字
   - ❌ 不是标准BCD（不是每半字节代表1位）
   - 💡 示例：0x05 → 5（代表"05"两位数字）

3. **计数器单位**
   - ✅ 开分码表/洗分码表记录的是**金额（分）**
   - ❌ 不是次数（与线下钢珠机的B5/B7不同）
   - 💡 需要乘以 turn_used_point 计算打码量

4. **校验顺序**
   - ✅ 先算SUM1（ADD累加），再算SUM2（XOR异或包含SUM1）
   - ❌ 不能颠倒顺序
   - 💡 发送和接收时都要验证两个校验码

5. **故障排除**
   - ✅ `EA E7` 会清除开分码表和洗分码表
   - ❌ 不可逆操作，数据会丢失
   - 💡 建议先执行"更换开分卡"保存数据

6. **开机信号**
   - ✅ 机版开机时会主动发送 `FAH`
   - 💡 收到后应重新初始化连接状态和登入

7. **错误处理**
   - ✅ 收到 `E1` 时机台只接受归0指令（`EA E7`）
   - ❌ 此时其他操作都会失败
   - 💡 应立即锁定机台，发送归0后解锁

8. **停止位配置**
   - ✅ 停止位为 **2**（与线下钢珠机的1不同）
   - ❌ 配置错误会导致通信失败
   - 💡 确认串口配置：9600-8-N-2

---

### 🔧 常见配置错误

| 错误配置 | 正确配置 | 症状 |
|---------|---------|------|
| 停止位 = 1 | 停止位 = 2 | 无法通信 |
| 使用3字节BCD | 使用4字节BCD | 数据解析错误 |
| 把码表当次数 | 码表是金额（分） | 打码量计算错误 |
| 不校验SUM1/SUM2 | 必须校验 | 机台拒绝指令 |
| 不登入直接操作 | 先登入再操作 | 收到C5失败回复 |

---

### 💡 最佳实践

1. **连接初始化**
   ```
   1. 打开串口（9600-8-N-2）
   2. 等待开机信号（FAH）或主动查询（EA C4）
   3. 发送登入指令（EA C5）
   4. 等待登入成功（A7 C5）
   5. 开始正常操作
   ```

2. **定时查询**
   ```
   每隔5-10秒查询一次账目（EA C4）
   检测外部按钮计数器变化
   记录游戏日志
   ```

3. **错误恢复**
   ```
   收到E1 → 发送EA E7 → 等待EF/EE → 重新登入
   连接断开 → 重新初始化 → 重新登入
   操作失败 → 检查登入状态 → 必要时重新登入
   ```

4. **数据记录**
   ```
   外部按钮计数器增加 → 记录游戏日志
   计数器异常减少 → 检查check_flag → 发送告警或忽略
   故障排除后 → 设置10秒check_flag → 避免误报
   ```

## 常见问题

### Q1: 为什么上下分总是失败（收到A5 C5回复）？

**A**: 未登入。必须先发送 `EA C5` 登入指令，收到 `A7 C5` 成功回复后，才能执行上下分操作。

---

### Q2: 开分码表和洗分码表的单位是什么？

**A**: 金额（分），不是次数。

例如：
- 开分码表 = 5204911 表示外部按钮累计开分 52049.11元
- 与线下钢珠机的B5/B7不同（B5/B7记录的是次数）

---

### Q3: 为什么数据解析总是错误？

**A**: 可能是BCD格式理解错误。

正确格式：每字节的**十六进制值转十进制**后代表2位数字
- 错误：0x05 → 5（1位数字）
- 正确：0x05 → 5 → "05"（2位数字）

示例：
```
十六进制: 05 14 31 0B
第1步转dec: 5, 20, 49, 11
第2步拼接: "05" + "20" + "49" + "11" = "05204911"
最终结果: 5204911
```

---

### Q4: 故障排除（EA E7）会清除哪些数据？

**A**: 
- ✅ 清除机台故障标记/故障灯
- ✅ 清除开分码表（外部开分计数器）
- ✅ 清除洗分码表（外部洗分计数器）
- ❌ 不影响服务端其他数据

**建议**: 如果需要保存码表数据，先执行"更换开分卡"操作查询并记录。

---

### Q5: 校验码计算总是不对？

**A**: 检查以下几点：

1. **计算顺序**: 先SUM1（ADD），再SUM2（XOR含SUM1）
2. **取最后2位**: 使用 `& 0xFF`
3. **数据范围**: 只对数据部分计算，不含校验码本身

示例：
```php
// 数据: A5 05 C0
$sum1 = (0xA5 + 0x05 + 0xC0) & 0xFF;  // = 0x6A
$sum2 = (0xA5 ^ 0x05 ^ 0xC0 ^ $sum1) & 0xFF;  // = 0x0A
// 完整指令: A5 05 C0 6A 0A
```

---

### Q6: 机台显示E-1，如何处理？

**A**: 记忆体异常，需要归0。

**处理步骤**:
```
1. 服务端锁定机台（has_lock = 1）
2. 发送归0指令: EA E7
3. 等待回复: EF（完整归0完成）
4. 服务端解锁（has_lock = 0）
5. 清除外部计数器（external_open_count = 0, external_wash_count = 0）
6. 设置check_flag（10秒有效）
7. 重新登入: EA C5
```

或使用**硬件归0**：
```
指拨4切ON → 倒数计时9→0 → 自动归0完成
```

---

### Q7: 如何区分开奖中状态？

**A**: 查看状态标志：

| 正常状态 | 开奖中状态 | 位置 |
|---------|-----------|------|
| `C9` | `CB` | 开分码表标志（EA C4回复） |
| `D8` | `D7` | 总押分标志（EA D8回复） |

当这些标志变化时，说明机台正在开奖。

---

### Q8: 转数如何计算？

**A**: 转数使用2字节，每字节转十进制后拼接。

示例：
```
转数数据: DC 1E 14
转数标志: DC（固定）
高位: 0x1E → 30
低位: 0x14 → 20
结果: 3020转
```

---

### Q9: 外部按钮计数器异常减少怎么办？

**A**: 检查是否故障排除导致。

**正常情况**（10秒内）：
```
故障排除 → 设置check_flag（10秒） → 计数器归零 → 识别为"故排归零"（不告警）
```

**异常情况**（超过10秒或无check_flag）：
```
计数器减少 → 无check_flag → 识别为"异常减少" → 发送告警 → 锁定机台
```

**建议**: 故障排除后立即设置 `check_flag` 缓存标记（10秒有效）。

---

### Q10: 如何实现打码量统计？

**A**: 

**公式**:
```
打码量（元）= 外部按钮金额增量（分）× turn_used_point
```

**示例**:
```php
// 开分码表从 5204911 → 5205011（增加100分）
$increment = 5205011 - 5204911;  // = 100分
$turnUsedPoint = 1.0;  // 从机台类别读取
$betAmount = $increment * $turnUsedPoint;  // = 100元
```

**注意**: 
- turn_used_point 存储在 `machine_category` 表
- 线下Slot的码表是**金额**，不是次数
- Redis存储单位是"分"，数据库存储单位是"元"
